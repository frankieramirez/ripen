## Phase 3 — release plumbing (still private)

Charted and worked as the [Release plumbing map](https://github.com/frankieramirez/ripen/issues/46), every ticket on it now closed. The map widened this phase to three things it never named: GitHub Actions was billing-blocked so no workflow had ever run, none of the release secrets were provisioned, and a config that passes `goreleaser check` is not a release. The Homebrew tap bullet this phase used to carry is gone — [ADR 0003](../adr/0003-distribution-channels-at-v1.md) fixes the five channels at `v1.0.0` and Homebrew is not one of them ([#48](https://github.com/frankieramirez/ripen/issues/48)).

- [x] Restore GitHub Actions billing so workflows can run ([#47](https://github.com/frankieramirez/ripen/issues/47)). Not a failed payment: the account's included private-repo minutes ran out with the spending limit at the default $0, and GitHub emits one combined annotation for both causes. A Pro upgrade cleared it, and `Go CI` then passed all five jobs — which retires the Phase 2 caveat above that CI green was unproven for the entire Go rework. The allowance is monthly and account-wide, so this can recur until the flip makes runners free.
- [x] GoReleaser config: linux/amd64+arm64 `FROM scratch` images to GHCR + Docker Hub (tags `vX.Y.Z`, `X.Y.Z`, `vX.Y`, `vX`, `latest`), linux+darwin binaries, checksums, Syft SBOM, keyless cosign, `attest-build-provenance`, CHANGELOG.md as release body ([#12](https://github.com/frankieramirez/ripen/issues/12)). Landed in [#42](https://github.com/frankieramirez/ripen/pull/42), but the config that ships is not the one #42 wrote. Nine follow-ups corrected it: the floating tags render only on a non-prerelease ([#56](https://github.com/frankieramirez/ripen/pull/56)), the image build copies the binary out of its per-platform directory ([#58](https://github.com/frankieramirez/ripen/pull/58)), provenance covers the archives and the checksums file instead of the raw binaries nobody downloads ([#61](https://github.com/frankieramirez/ripen/pull/61)), the checksums are signed into a Sigstore bundle by a wrapper that cannot silently produce nothing ([#62](https://github.com/frankieramirez/ripen/pull/62), [#78](https://github.com/frankieramirez/ripen/pull/78)), cosign installs with an installer that can fetch a 3.x at all ([#73](https://github.com/frankieramirez/ripen/pull/73)), the notes file is written outside the work tree because `goreleaser release` refuses a dirty one ([#74](https://github.com/frankieramirez/ripen/pull/74)), the changelog section actually reaches the release body ([#75](https://github.com/frankieramirez/ripen/pull/75)), and the release refuses in front of the provenance step rather than going red behind it ([#76](https://github.com/frankieramirez/ripen/pull/76)).
- [x] `flake.nix` in-repo builds from source ([#12](https://github.com/frankieramirez/ripen/issues/12)) — written and verified on a real Nix install, with a `nix build` CI job so it cannot rot ([#52](https://github.com/frankieramirez/ripen/issues/52)). Its `version` is a constant a flake cannot derive from a tag: bump it in the release commit. The channel also trails the archives on Go standard-library patches by roughly a fortnight, permanently; that gap is gated by `.github/nix-vuln-baseline.txt` and a weekly `flake.lock` bump, not fixed ([#69](https://github.com/frankieramirez/ripen/issues/69)).
- [x] Dry-run: `goreleaser release --snapshot` produces the full artifact set locally ([#53](https://github.com/frankieramirez/ripen/issues/53)). Clean on `52b2c39` with `--snapshot --clean` and no `--skip` flags, run three times with byte-identical output: 35 artifacts, 15 of 15 non-image paths present. It failed the first time, and that failure is what produced [#57](https://github.com/frankieramirez/ripen/issues/57), [#59](https://github.com/frankieramirez/ripen/issues/59), [#60](https://github.com/frankieramirez/ripen/issues/60) and [#63](https://github.com/frankieramirez/ripen/issues/63).
- [x] Provision the private Docker Hub repository and the release token ([#51](https://github.com/frankieramirez/ripen/issues/51)). Done 2026-08-19 with [`.github/release/provision-dockerhub.sh`](../../.github/release/provision-dockerhub.sh), which is also the rotation procedure. The repo is private with the #19 description, both secrets are set, and the token is account-wide Read & Write — per-repository scope is a Pro/Team feature. Scope, storage and rotation: [release credentials](../release-credentials.md).
- [x] Rehearse a real release with `v0.1.0-rc.1`, then delete it ([#54](https://github.com/frankieramirez/ripen/issues/54)). Five tagged runs to get one that published, every fault in a part `--snapshot` skips. What passed matters as much: `cosign verify-blob` succeeds with the exact certificate-identity regex in the release footer, every image manifest verifies on both registries, both carry both platforms at one digest with only the two exact-version tags, and the GHCR package inherited privacy with no explicit flip. Release, tag, GHCR package and both Docker Hub tags were deleted; scaffolding removed in [#77](https://github.com/frankieramirez/ripen/pull/77).

**What Phase 3 could not prove.** GitHub does not persist build provenance for user-owned *private* repositories, so [#76](https://github.com/frankieramirez/ripen/pull/76) makes the release refuse before it publishes anything it cannot attest. That guard, and the four fixes that landed after the rehearsal, cannot be exercised end to end until the repo is public. **The Phase 6 `v1.0.0` tag is therefore the pipeline's next full proof, not a formality — budget for a failed first tag.**
